# Workflow coverage review for the Visual Design Guidelines

Date: 2026-10-08. Status: source audit and proposed additions; not user-approved and not a claim of browser verification. No application or design-service changes made.

Sources: `src/main.tsx`, every rendered component in `src/`, `src/journals.ts`, `src/storage.ts`, README, `design/original-spec-excerpt.md`, `design/design-contract.md`, and guidelines revision 1. File/line references below identify the inspected version; later edits may move them. Penpot is outside this audit's ownership.

## Coverage and terminology decisions

The product contains four in-app views, not URL routes: Verse map, Reading history, Reading patterns and Your data. The map stores references and recorded activity, **no Bible text**. Personal notes belong to a reading, not an independently editable verse-note object. Verse inspection lists matching reading events; reading detail shows notes. Do not specify a Bible reader, commentary browser, note notebook, live synchronization, range-drag selection or gesture panning as existing behavior.

The guidelines' current visual foundation is useful but section 7 is too broad to cover the complete application. Add the detailed rules below and explicit state specimens, using the existing typography/color/spacing tokens. This document proposes component-level rules, not a competing palette.

Resolve these naming/semantics distinctions throughout the document:

- **Current journal** is the normal recording destination and default viewing journal. **Recording in** can override the destination for a new reading. **View readings** filters displayed evidence independently. **Map scope** limits visible verse geography independently of journal/date evidence.
- **Reading records/session counts** are not always identical to **encounters**: copies share an encounter across journals. Multi-journal frequency statistics deduplicate encounters; displayed history and session counts still contain individual records. Do not present them as one interchangeable denominator.
- **Archive** preserves a journal for read-only inspection. **Clear** moves its readings to Trash. **Delete empty journal** permanently removes the journal. **Purge Trash** permanently removes readings. Avoid using “delete” for all four.
- **Undo** lasts 30 seconds in the current tab; **Trash** lasts 30 days in persisted browser storage. Navigation does not end Undo; reload/closing does. Trash is excluded from map/history/patterns/backup until restored.
- **No recorded reading**, **no reading in this period**, **no search match**, **empty selected journal**, **no journals selected**, and **sample data** require different messages, recovery actions and examples.

## A. Shared shell, orientation and viewing controls

**Current:** `main.tsx:768` renders brand/About trigger, journal picker and Manage journals, four-view navigation, local status, breadcrumb, persistent logging action, footer, global errors, sample notice, archived notice, success toast and multiple Undo notices. `ReadingViewControls.tsx` renders applied journal/date summary and a disclosure with a draft. Period modes are all time, this month, this year and inclusive custom dates. Journal modes are current, all active and selected; selected journals may include archived journals. Apply commits; Cancel/Escape discards; Reset restores current journal/all dates. Chips clear period or remove journals. An explicit destination hint accompanies aggregate viewing.

**Required additions:** Specify shell states at 1440/768/390/320px, selected navigation, journal picker long-name wrapping, collapsed controls and expanded controls. Keep current evidence scope visible above all three analytical views. Use a readable summary rather than several similarly dominant banners. Place recording destination separately from viewing scope; label both. Give chips full names and at least the document's ordinary target footprint. Draft selection styling must never imply applied results. Custom start/end labels remain visible; validation belongs in the panel and retains both dates. Removing the last selected journal must show “No journals selected” and a way to choose journals, not first-use onboarding. When archived inspection is active, show archive status and Restore/Return actions with the viewed name. Hidden/disabled editing requires an explanation in context. Sample and archive notices use neutral information styling, never failure red.

**Proposed component mapping:** shell and status region in `main.tsx`; scope summary/panel/chips in `ReadingViewControls`; shared status tokens in `design.css`. Show compact and expanded view-control reference frames, custom-date error, all/selected journals and archived/sample states.

## B. Journal lifecycle

**Current:** `main.tsx:2540–2697` has Manage journals, create and rename dialogs; suggestions Sermons/Small Group/Memorization; a required name with 60-character maximum. `journals.ts:58` trims names and rejects empty/duplicate case-insensitive names. The manager lists active/archived journals, Rename, Clear active readings, Delete nondefault journals, Inspect archives and Archive/Restore nondefault journals. The default journal may be renamed/cleared but never archived/deleted. Repository writes preserve archive state on rename. Archive does not discard data. Creating/renaming closes on success with status; errors preserve input. `main.tsx:2460` permits permanent journal deletion only when it is empty, offers export and explains existing Trash may need a different destination.

**Required additions:** Define journal-manager rows with name/status first, count/context second, regular lifecycle actions third and destructive actions in a clearly separated area. Long names wrap without pushing actions outside the dialog; mobile stacks actions. Active/archived badge must include text. Creation has one primary Create journal action; rename has Save name, with the old name visible in context. Suggestions are optional secondary buttons. Add blank, duplicate, maximum-length, saving, success and concurrently renamed/deleted states. Distinguish archive and restore from destructive danger buttons. Explain nondefault restrictions and disabled Delete reason next to the action. Permanent deletion uses danger emphasis and exact journal name; cancellation must be equally reachable. Keep backup available in the confirmation. No extra confirmation is needed merely for ordinary archive/restore unless the design introduces one for a concrete reason.

**Mapping:** existing `Dialog`, journal manager/editor JSX, journal validation/repository. Suggested extraction into JournalManager/JournalEditor is a future implementation choice, not an existing component. Reference frames: mixed active/archive list, long name, invalid create, valid rename, nonempty delete blocked, empty delete permitted.

## C. Map and verse inspection

**Current:** `main.tsx:1102–1432` shows scope-relative verses recorded, view-relative session count and last reading; map heading; book/chapter selectors; Go to passage disclosure; current scope and Whole Bible reset; `MapDisplayControls` with Combined/Recency/Frequency, Flow/Fixed and 4–14px cell-size zoom in increments of two/reset to four. `Heatmap` is a continuous canvas with a hover overlay and book highlight; keyboard arrows inspect, Home/End reach scope boundaries, Enter opens verse detail. Canvas scrolls when keyboard inspection would leave the visible area. Reference search accepts one continuous range; inspector accepts exactly one verse. The textual inspector includes count/last date, previous/next controls, open details and keyboard help. Combined legend expands to a two-axis bucket matrix; single metrics have bucket swatches. Verse dialog shows count/first/last and matching event references/dates/journals, View chapter and Log this verse. It does not display Bible text or editable verse notes.

**Required additions:** Specify metric/layout selected, hover, focus, boundary-disabled zoom/inspection, collapsed/expanded legend and long passage scope states. Keep map metric colors independent of UI state color. Define a dual-contrast locator/outline over dark and pale cells without replacing data encoding. Book hover is transient; selected verse is persistent orientation; distinguish these explicitly. A tooltip must remain within the scroll viewport and readable at edges; touch must not rely on hover. Preserve exact count/date equivalents in text. Scope search error belongs beside its field and keeps the last valid map. A parsed passage spanning books is one continuous scope; multiple discontinuous passages are invalid for this control even though logging accepts them. Changing a book resets chapter and passage scope; Whole Bible resets geography, not journal/date filters. Fixed layout preserves canonical column positions; it may scroll horizontally while surrounding controls reflow. Do not add permanent gaps at book/chapter boundaries. Legends must explain gray's metric-specific meaning and future-date behavior; counts and dates resolve ambiguity. Reference frames: whole Bible, chapter, cross-book range, invalid/discontinuous search, text-inspector invalid range, zero in period with all-time evidence, never recorded, selected dark/pale cell, single-metric and full combined legends, zoom endpoints.

**Mapping:** `Heatmap.tsx`, `layout.ts`, `MapDisplayControls.tsx`, `MetricLegend.tsx`, textual inspector/verse dialog in main; metric bucket semantics in `domain.ts`. A desktop detail pane is proposed; current detail is `Dialog`. Preserve return scope and selection when adapting to a pane/sheet.

## D. Capture, parsing, editing and save recovery

**Current:** `main.tsx:438–620`, `1956–2074`: new/edit dialog; visible Recording in selector, disabled during editing; passage field initially focused; examples disclosure; live normalized parser preview and unique count; reading date defaults today, rejects invalid/future dates; optional notes; legacy timestamp explanation; Save reading/Save changes; saving text and duplicate-submit guard. New logs are date-only; editing a known instant without changing its calendar date preserves the instant, while a date change converts it to date-only. Success closes the dialog and announces the destination. Show this reading clears date constraints, selects the recorded journal and focuses the first saved range. Write failures retain the draft. Cross-tab conflict dialog supports Keep mine, Use theirs, Save as new reading when removed, Discard edit, Delete current version or Cancel according to conflict type.

**Required additions:** Define blank, typing, parsed-valid, parsed-invalid, date-invalid, saving, saved, hidden-by-view, storage-failed and conflict specimens. The parser preview is a bounded status/error region with icon plus text; keep normalized references and unique count distinct from the raw editable input. Notes preserve line breaks and wrap long tokens; no page overflow or destructive truncation. Validation needs visible association with the responsible field, focus on the invalid input on submit and retained passage/date/notes/destination. Do not apply success treatment to a partial invalid input. Disable the save action for unusable references, with explanation; keep Cancel available. Distinguish an edited reading's original journal from change-of-destination workflow. Success should name passage, date and journal sufficiently to verify the action, and remain discoverable in history after a transient toast. Show this reading should disclose when changing the user's filters. Conflict layout must identify “Your draft” and “Saved in another tab” before resolution choices; make the preservation consequences explicit. Recoverable failures should be readable inside/above the active surface, not hidden behind an inert modal backdrop. Long conflict notes need scroll/wrap and full-text access. Imported future/legacy dates need correction guidance without being mistaken for newly permitted future logging.

**Mapping:** capture and conflict JSX in main, `Dialog`, parser/date APIs in `domain.ts`; shared field/error/status components are proposed extractions. Save conflict currently displays remote content, not a full draft comparison; a side-by-side comparison is a proposed addition.

## E. History, notes, move/copy and deletion

**Current:** `main.tsx:1434–1602` searches raw/normalized references, notes and date forms; groups records by day; opens detail from date or passage; shows journal, verse count and notes excerpt. More actions reveals icon-only Move/Copy/Delete for editable records. `ReadingDetail` shows full normalized references, formatted date, journal, count, notes or No notes, and Edit when permitted. Sample/archive records have no editing controls. Transfer dialog selects another journal; copy IDs are new but retain encounter identity. Same-journal copies are disallowed; changing copied date/ranges creates a new encounter. Repository rejects archived/missing destinations and concurrent source changes. Delete confirmation identifies passage/date; clear identifies journal/count and preserves readings added after the confirmation snapshot. Both create Trash and Undo.

**Required additions:** Define day group/list row/expanded actions/search-match/no-search-match/empty-journal/filtered-empty/long-note/read-only detail states. Use passage as the primary row title, date/journal metadata next, count and preview last. Full notes belong to detail and must retain whitespace; empty notes are neutral. Contextual actions require visible Move/Copy/Delete labels on touch and keyboard, not only an icon's accessible name. Move/copy dialog shows source passage/date/journal, destination, effect and one named submit action. Eligible destinations must be active; explain if none exists and offer journal creation or return. Clarify that copies add a history record without double-counting one encounter across selected journals; notes-only editing does not imply a second encounter. Transfer error retains destination and context. Deletion/clear uses danger styling only for the destructive action, with a normal Cancel and recovery duration. No optimistic removal until persistence succeeds. Clearing another journal must name that actual target in confirmation and feedback, not whichever journal is currently viewed.

**Mapping:** History and transfer/delete/reset JSX, `ReadingDetail`, repository copy/move/reset/delete APIs. Proposed labels and eligible-destination filtering require implementation; do not say they already exist.

## F. Undo, Trash and recovery

**Current:** `main.tsx:125–174`, `934–969`, `1770–1855`, `2430–2458`: multiple Undo notices with per-operation countdown, Dismiss and error; Trash groups with deletion/expiry dates, full reading context, destination selector, Restore and permanent purge confirmation. Undo remains during view/journal navigation. Restore can use original active journals or a selected active destination; restoration is atomic and refuses ID collisions. Expired/already restored/purged entries, unavailable original journals and duplicate IDs return explicit errors. Empty Trash is labeled. Purge is permanent and cannot be undone.

**Required additions:** Recovery is a durable workflow, not a generic short toast. Reserve a nonobscuring status region; stack multiple operations with exact context and keep focus stable when countdowns change. Announce initial status once, not every second. Expired Undo should offer Your data → Trash rather than suggest all recovery ended. Dismiss must not delete Trash or undo the underlying operation. Trash groups need clear reading count, original journal(s), deletion and expiration, expandable content for many long notes, and restoration destination. Restore is the main action; purge is separated and danger styled. If original journal is archived/missing, show explanation next to destination before a failed restore where possible. Retain chosen destination and error on failure. Purge confirmation identifies the affected group/count and permanent consequence; Cancel remains visible. After success preserve neighboring group orientation and announce result. Test one/many groups, expired Undo, empty Trash, unavailable original destination, ID collision, failed/successful restore and purge.

**Mapping:** Undo/Trash JSX in main and `storage.ts:273` restoration; proposed reusable RecoveryNotice/TrashGroup components. Make explicit that export omits Trash and that restoring first includes the records in the next backup.

## G. Reading patterns and quantitative language

**Current:** `main.tsx:1603–1708`: overview with session count/books/revisited count; unique verses, revisited verses and total verse readings; collapsed canonical-order all-66-books breakdown with coverage bar, percentage and absolute fraction; clicking a book opens scoped map; ten repeated verses sorted by count then canonical order, opening verse detail; neutral no-repeat explanation. Applied journal/date controls govern evidence. Geographic map scope does not limit these view-wide pattern statistics. Aggregate statistics deduplicate copied encounters.

**Required additions:** Every number must state its unit and denominator/scope. “Unique verses” means at least one recorded encounter in the applied evidence view; coverage uses that book's verse total, not sessions or spiritual completion. Label bars “Recorded verses” or “coverage of recorded history,” never goal/progress achievement. Keep canonical order and tied-list rule visible. Explain record/session versus encounter distinctions in aggregate views. Add empty view, one reading, repeated readings, filtered period and copy-deduplicated examples. Empty percentages display a neutral zero/unrecorded convention consistently; “—” means no record, not unknown total. No warning/red for unrecorded books, celebration for high percentages, score-like giant figures or rank badges. Book/detail navigation retains the applied evidence view. Progress bars need equivalent textual fraction; list controls need full accessible names and visible focus.

**Mapping:** stats cards/book grid/return rows in main, `aggregateStats` in `journals.ts`, `deriveStats` in `domain.ts`. Consider renaming CSS `.progress` to a descriptive coverage concept during implementation without altering semantics.

## H. Data, backup/import, storage and privacy

**Current:** `main.tsx:634–683`, `1710–1910`, `2141–2212`: privacy/storage explanation; full-journal JSON export with count and persistent initiated-at/unexported-change state; exporting disable; success explicitly says download initiated, not saved; errors preserve backup status. Import picks JSON, parses and validates, previews journal/readings/duplicate counts, colliding-name suffixes and older-default-journal behavior, then merges atomically preserving concurrent changes and existing record IDs. Invalid JSON/schema/versification/date/reference/ownership returns an error. Import into existing archived destinations can fail until restored. Data view includes Trash and About disclosure with canon, numbering, data/database versions, offline caveat, separate browser/origin storage and source-code download. Source code is not personal-data backup. Startup load has ready/storage-ready flags, storage-open/upgrade-blocked errors and disabled writes. There is no account/cloud/telemetry; production offline availability depends on a complete first load and supported origin.

**Required additions:** Specify export never initiated/current snapshot matches/unexported changes/export in progress/initiation success/export failure; a status change is not a guarantee that the downloaded file is durable. Import needs file-selected/reading/invalid/validated/no additions/duplicate-heavy/name-collision/legacy/archive-conflict/merging/complete/write-failed states. Keep selected file name and specific recovery action visible (proposed; current preview lacks filename). Import preview should display real file format version rather than a hard-coded older version. Label counts as additions, existing IDs kept and journals renamed; show exact rename mapping. One primary Merge action and Cancel. Failure preserves the validated preview; malformed input does not mutate records. New journals and Trash are not implicitly merged into one history. Full export ignores view filters and includes empty/archived journals, but excludes Trash. Provide that scope adjacent to Export. Downloads/technical details remain secondary to personal-data safety.

Storage loading/failure must not masquerade as empty first use or label data as “saved locally” before storage opens. Keep shell and retry/recovery guidance, disable write/import actions while unavailable, and allow safe sample exploration with clear separation. No silent claim of successful persistence. Use plain “this browser on this device” in primary copy; put IndexedDB in technical details. Distinguish privacy, portability and durability: local storage is private but not automatically backed up. Do not imply account sync. Offline status is not a guarantee for the dev server or a never-loaded origin. Service-worker failures currently have no user-facing status; a live Offline indicator would be a proposed feature.

**Mapping:** data/capture/status JSX and `storage.ts` repository, `backup.ts`, `journals.ts` validation; optional ImportPreview/DataStatus extractions. Storage-readiness gating of all import/mutation surfaces is a proposed consistency requirement, not uniformly present now.

## Cross-component state contract to add to the guidelines

Apply these rules to every input, disclosure, row action, segmented control, dialog and temporary surface:

1. Default/hover/pressed/selected/focus/disabled/busy/error/read-only states use one semantic vocabulary. Selection has text or a marker in addition to hue. Disabled actions explain the unavailable prerequisite when consequential.
2. Field label → field → help → field error is the reading order. Group errors identify the failed operation and keep the user's input. Read-only is not interchangeable with loading/disabled.
3. A write's busy state names the operation (Saving, Moving, Copying, Restoring, Importing, Exporting), avoids layout shift and double submissions, and does not erase context. Current code only has explicit Saving text for some actions; remaining labels are proposed.
4. Dialogs have a visible title, reachable labeled close/Cancel, trapped focus, inert background and focus restoration. Existing `Dialog` implements these mechanics; note that backdrop/Escape currently closes forms without an unsaved-change warning. If guidelines require retained drafts after accidental dismissal or a discard prompt, mark that as new behavior rather than existing protection.
5. Long journal names, multi-range references, date/provenance strings and notes wrap; full detail remains accessible. Test 60-character journal names, multiple books, multi-paragraph notes and unbroken strings. Dialog body can scroll without hiding title/context/actions; do not cover focused controls with a sticky footer or mobile keyboard.
6. Success status and recoverable Undo are separate patterns. Generic success currently times out after 4.5 seconds; essential recovery cannot depend on that timeout. Alert/status placement must work while a modal is open and with bottom navigation/safe areas.
7. Active scope/selection survives appropriate inspection return. Current page/sample navigation resets window scroll; preserving exact map scroll through all view transitions is a proposal needing implementation verification.
8. Reduced motion freezes illustrative first-use animation; demo Pause/Play remains labeled. Focus, errors and saved-state feedback remain meaningful with animation disabled. Skeletons must not look like personal records or changing metrics.

## Source-level inconsistencies to resolve before calling the guidelines complete

These are observed discrepancies or implementation gaps, not claims of tested runtime bugs:

- Revision-1 contract specifies 44/34px page headings, a spacing step of 40px and 44px targets described under WCAG; guidelines specify smaller returning titles, a scale including 48px and correctly distinguish the 24px AA minimum from 44px product preference. Declare which revision governs and supersede old measurements explicitly.
- Transfer options currently include archived destination journals, while repository rejects them. Guidelines should require eligible active options plus an explanatory empty state.
- Clear feedback uses `currentJournal.name`, which may differ from the journal selected for clearing in Manage journals. Require exact operation target consistently.
- Import validation label renders v1/v2 from a legacy flag, despite current v3 backups. Require metadata-derived accurate label.
- Global write errors can be outside the active modal; add modal-local feedback placement rules. Conflict UI currently centers reading resolution even when `runWrite` receives journal conflict data; journal-specific resolution/state design needs explicit treatment.
- Loading uses a map-local indicator only when the map is shown; first-use can render before storage readiness is known. Ensure initialization has its own visual state.
- Search has a no-match message and history has an empty-view message, but its header is pre-search count. Specify whether that count is total visible records or search results and label accordingly.
- History session counts use records; multi-journal verse statistics use encounters. Explain this difference rather than implying identical counting units.
- Verse event rows are plain date/reference/journal entries, while full notes live in ReadingDetail. Connecting event rows to notes/detail is proposed, not already implemented.
- Import selection/loading has no explicit busy/filename state; Trash restore/purge and transfer have disabled busy controls but often no operation-specific busy label/success status. Guidelines need these states even before code provides them.

## Required reference and acceptance inventory

The comprehensive document should name these state families as required implementation/design evidence, not mark them already verified:

- Shell: all four views, narrow navigation, long journal names, active scope/destination, archive and sample notices.
- First use: storage loading, storage unavailable, personal empty, illustrative paused/reduced-motion demo, sample populated and return to personal.
- View filtering: draft vs applied, custom invalid dates, selected/all/archived journals, zero selected, filtered empty, reset.
- Map: whole/book/chapter/passage scopes, all metrics/layouts, zoom bounds, hover/focus/selection over extremes, edge tooltip, textual inspector and full legend, never versus outside period.
- Capture: blank/valid/invalid/multi-range/long-note/date/legacy states, saving/success/hidden success/write failure, new/edit destination, every cross-tab resolution branch.
- History/detail: grouped/search/none/long-content/read-only; eligible and unavailable transfer destinations, move/copy success/error; delete/clear snapshot and exact target.
- Journals: create/rename validations, manager active/archive actions, archive inspection/restore, protected default, blocked/permitted permanent delete and concurrent lifecycle conflicts.
- Patterns: empty/one/repeated/filtered/aggregated-copy cases, 66-book disclosure, canonical ties, context-preserving map/detail navigation.
- Data/recovery: every export/import status, malformed/unsupported/legacy/collision/archive input; single/multiple Undo, timeout/reload; Trash no entries, destination failure, collision, restoration and permanent purge.
- System: blocked upgrade/storage write failure, long content at 320px, 200% text size, keyboard dialogs/disclosures/canvas/text alternative, touch, reduced motion, safe areas/mobile keyboard and status focus occlusion.

Use existing central tokens and components for all of these; add named reusable patterns only where needed. Browser validation must test actual behavior and rendered color/target/focus states; this repository audit establishes required coverage, not accessibility conformance or user-research validation.
