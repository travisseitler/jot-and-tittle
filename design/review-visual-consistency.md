# Visual consistency review — proposed r2 canonical rules

Date: 2026-10-08. Scope: read-only review of `visual-design-guidelines.md`, `design-contract.md`, `src/design.css`, `src/styles.css`, and relevant app/layout code. Only this report was added. Recommendations below are agent proposals, not user approval, implemented behavior, accessibility certification, or independent inspection of Penpot. Penpot r2 particulars were supplied by the coordinating agent.

## Migration conflicts to resolve before implementation

R 1 and current CSS reflect the prior shipped pass. Their differences from r2 are migration work, not evidence that the earlier implementation violated a later specification.

1. **Reference/version authority:** the contract declares r1 local SVG canonical and Penpot unavailable. The current working draft is Penpot r2 with four reference viewports. Preserve r1 as historical evidence; update the contract to name r2 as the editable working reference, its stable identifiers, draft status, export revision and app state mappings. Do not imply r1 screenshots verify r2.
2. **Sidebar and breakpoints:** contract and `styles.css` specify 228px desktop; CSS narrows to 200px at 1200 and 180px at 950. R 2 desktop uses 192px. Existing media rules at 1650/1200/1100/950/700/360 produce overlapping behavior. Establish the exact responsive bands below rather than carrying every historical override forward.
3. **Heading scale:** guidelines propose broad 28–32px desktop and 24–28px mobile ranges; contract states 44/34; `design.css` implements 44/34/32. R 2 tokens stop at 32. Choose returning page title 32 desktop / 26 phone, without a separate oversized first-use hero. Section and passage roles need fixed assignments.
4. **Font/root sizing:** guidelines specify system sans and Georgia. `styles.css` prefers locally available Inter and sets root size to 14px. That makes a nominal 1rem different from the intended 16px baseline. Use the system stack and 100% root size, with rem equivalents. Inter and Source Serif 4 in Penpot are intentional proxies, not instructions to load fonts into the app. Record expected font-metric differences.
5. **Shape/spacing:** guidelines allow control 6–8/panel 10–12; contract uses 7/12; CSS contains 4/5/6/7/8/9/10/12 plus full pills. R 2 fixes 8/12. Contract includes 40 spacing while guidelines/R 2 include 48. Canonicalize 8 controls, 12 containers, 0 map cells/rows; reserve 999 only for intentional tags. Use the seven supplied spacing steps.
6. **Semantic names:** guidelines use `action.primary.hover`; r2 uses `action.hover` because its token tool cannot have a leaf and nested namespace at the same path. Adopt `action.hover` in all reference documents, mapping it explicitly to CSS `--action-hover`.
7. **Weak essential boundaries:** `.secondary` and scope-control outlines use `--line` (#DCE1D5), while input borders include #BAC5AE/#D9E0CE. Guidelines already identify subtle border contrast as inadequate for sole control recognition. Use #7B8B77 for actual outlined controls; retain subtle rules only for separation.
8. **Focus inconsistency:** guidelines say 2px ring/2px offset; late CSS says 3px #172915/3px offset/6px white shadow for several elements. Anchors retain an earlier green ring, and inputs retain separate `:focus` styles. Use one focus-visible rule including anchors; let error plus focus coexist. Do not overwrite a selected state with the focus state.
9. **Unmapped colors/states:** sidebar #EEF0E7, active navigation #E0E9DA, multiple pale green panels, muted #65705E and text #485B46 bypass semantic tokens. Destructive buttons use #9E624B and invalid parser panels remain muted brown. Disabled behavior is blanket opacity .4. Define explicit surface and interaction state tokens; retain existing domain palette separately.
10. **Density and target mismatch:** ordinary buttons/selects default to 36px and icons 36px, coarse pointer 44px; r2/spec proposals use 48px primary/fields. Inspector buttons can be 40px. Several essential labels and history metadata are 12–13px. Set component sizes below and let rows grow for content/text resize.
11. **Typography/brand inheritance:** numerical summaries currently use 30px Georgia and some decorative uppercase labels 11px. Proposed operational type should use tabular sans numerals 24px and meaningful metadata 14px. Keep Georgia for wordmark and named editorial headings; avoid global h3 inheritance for every operational section.
12. **Motion and overlays:** contract says no added animation; guidelines allow 120–180ms. CSS has a 20s looping demonstration and varying shadows, z-index 25 nav/50 dialog/100 toast. Pick exact duration/easing/layer rules and retain pause/reduced-motion controls for the demonstration. A toast above a modal must not obscure modal actions.
13. **Map size vs fixed-grid:** r2 default 4px marks/5px stride agrees with `Heatmap.tsx`'s `stride-1` rule only when zoom=5. Fixed-grid layout always uses 160 columns (`layout.ts`), so it needs 800px at default stride. That must scroll within the visualization on small screens; surrounding UI must still reflow. A fixed 800px canvas must not become page overflow.
14. **Detail layout ambiguity:** “at least about two-thirds”, 320–400px detail and 640px map minimum cannot all be met in the supplied 1440 layout: 1440−192−64=1184; a 320px pane plus 24px gap leaves 840px, about 71%, but 400px leaves 760px/about 64%. Fix 328px pane and the 1248px viewport threshold supplied for r2; do not implement a range based on aesthetics.

## Canonical token schema

Keep the current 26 r2 tokens and add roles only when a component uses them. CSS names use kebab case; design names use dot namespaces. Values below are proposed exact defaults, not replacements for browser contrast checks.

- Existing surfaces: `surface.page=#F7F5EF`, `surface.panel=#FFFEF9`. Add `surface.sidebar=#EEF0E7`, `surface.disabled=#EEF0E7`, `surface.error=#FFF1ED`, `surface.overlay=rgba(41, 57, 46,.40)`.
- Existing text: `text.primary=#29392E`, `text.secondary=#5E6A5B`. Add `text.onAction=#FFFEF9`, `text.disabled=#5E6A5B`; placeholders use secondary, not lower opacity.
- Existing action: `action.primary=#365640`, `action.hover=#294632`. Add `action.pressed=#233C2C`, `action.disabled=#DCE1D5`. Selection uses existing `selection.surface=#E7EEE3`, with primary text and forest marker. Secondary/quiet hover uses selection surface; press also adds an inset forest outline, rather than another pale-green color.
- Borders: existing `border.subtle=#DCE1D5`, `border.control=#7B8B77`. Error boundary uses `status.error=#963F35`. Existing `focus.ring=#29392E`; add `focus.separator=#FFFEF9`.
- Error/destructive: existing `status.error=#963F35`; add `status.errorHover=#7F322B`, `status.errorPressed=#692720`. These require rendered state contrast verification. Success uses forest with explicit success text/check icon; informational status uses primary/secondary text and panel surface. No extra blue/green palette is necessary.
- Existing spaces 4/8/12/16/24/32/48; existing type 14/16/20/24/26/32; add type.30 for the established tablet title; existing radius.control 8/radius.panel 12. Add size.control 44, size.primary 48, size.field 48, size.icon 20, size.mapCell 4, size.mapStride 5. Control/map sizes are CSS pixels; body/type values are rem-based. Map sizes are visualization geometry, not text sizes.
- Add motion.feedback 120ms, motion.overlay 180ms, motion.easing=`cubic-bezier(.2, 0, 0, 1)`; elevation.overlay=`0 12px 32px rgba(41, 57, 46,.16)`; layer.sticky 10/navigation 20/popover 30/modal 40/status 50. Prefer a toast inside the active modal layer when that modal initiated the operation.

Use all tokens in both reference and implementation; aliases such as `--paper` may remain temporarily but resolve to a single semantic source. Do not redefine muted later in `styles.css`. Avoid alpha on essential text/borders. Do not use UI status tokens to change metric data.

## Exact typography and brand assignments

Root 100%, operational stack `system-ui,-apple-system,BlinkMacSystemFont,"Segoe UI",sans-serif`; editorial stack `Georgia,"Times New Roman",serif`. Font weight 400 body/editorial, 600 headings/labels/actions. Notes and all controls remain operational sans.

- Wordmark: 24px/32px Georgia 400, normal tracking; preserve spelling **jot & tittle**. Small brand descriptors 14px/20px sans, sentence case. Do not reproduce tiny decorative captions on phone.
- Page title: 32px/40px Georgia 400 desktop>=1024; 30px/38px tablet 768–1023; 26px/34px phone below 768. First-use title follows the same role.
- Section heading: 24px/32px Georgia 400 for primary map/history headings; 20px/28px sans 600 for utility/dialog subdivisions.
- Dialog title: 24px/32px Georgia 400. Selected passage: 20px/28px sans 600.
- Notes/input/body: 16px/1.65 (26.4px default) sans 400; fields use 24px line-height; notes maximum 65ch, preserve paragraph breaks and break long strings.
- Navigation/button/label/metadata/helper/status: 14px/20px sans; labels/actions 600, metadata/helper 400. No essential 12px captions. Summary counts 24px/32px sans 600, tabular numerals; dates 14px/20px sans 400. Use font-feature numeric settings rather than character spacing.

Type roles resize with user font settings. These are defaults, never fixed-height text boxes. No remote font requests; include the Penpot proxy caveat in visual comparisons rather than adjusting app tracking until proxy screenshots happen to match.

## Responsive and composition rules

Canonical r2 bands supplied by the coordinating agent after inspection of the tablet draft: phone<768; tablet 768–1023; desktop>=1024. Desktop sidebar192px; tablet has a full-width brand/journal header and horizontal four-item top navigation; phone has bottom navigation. Main gutters desktop 32/tablet 24/phone 16, including 320px. Do not shrink working 14–16px type at 320 or add a separate 12px gutter; optional phone navigation labels may be 12px with 44px targets.

- Desktop main usable width=`viewport−192−64`. At 1440 this is 1184px, aligned left at 224px. Page sections gap 32; map interior16; bounded field content 560px. Header minimum 64px; sidebar rows 44px minimum with 20px icons and 12px gap.
- Adjacent selected-range detail 328px plus 24px gap is allowed only when usable width>=992px (viewport>=1248px), leaving 640px map minimum. At 1440 the map remains 832px. Say “at least 640px” rather than promise two-thirds at every width. At 1024–1247 use an accessible dialog or separate content view; preserve scope, position and selection.
- Tablet at 768 leaves 720px content (768−48), without a sidebar. Use full-width brand/journal context and horizontal four-item top navigation; stack map controls/summaries naturally. No two-column first-use composition. Side detail cannot open alongside map.
- Phone: one column, journal/reference context above map; labeled four-item bottom navigation, each target 44px minimum, minimum total strip 64px plus safe-area. Header/action region sticky only while unobscured focus can be maintained. Reserve strip height+16px in content; announcements sit above it or in normal flow. Notes remain 16px.
- Map default 4px square mark/5px stride, uninterrupted canonical sequence. Fit mode recalculates column count; fixed 160-column mode has 800px internal width. Zoom changes geometry only; clamp scrolling to visualization region. Provide labeled reference input, keyboard equivalent and selected-reference text. Long controls wrap; tabs overflow by wrapping or a labeled scroll region, never clipping primary labels.
- Verify 1440×1000, 768×1024, 390×844, 320×720, plus 1023/1024 and 767/768 boundaries and 200% text resize. Viewport screenshots alone do not test text resize.

## Component state contract

States are dimensions, not mutually exclusive screens: interaction(default/hover/pressed/focus), availability(enabled/disabled/read-only), process(idle/saving/loading), validity(neutral/error), and selection(selected/unselected). Focus may coexist with error or selection; saving does not erase the button label/context. Hover applies only to devices that support it.

- **Primary:** minimum 48px high, inline padding 16, gap 8, 20px icon, 14/20 weight 600, radius 8. Default forest/onAction; hover action.hover; pressed action.pressed; focus 2px ring with 2px offset and 2px panel separator; disabled disabled surface/secondary text without opacity; saving same dimensions, stable “Saving…” label plus decorative progress mark, aria-busy, prevent duplicate submit. Each state keeps a text label.
- **Secondary:** minimum 44px, same padding/icon/type/radius, panel background/forest text/control border1px; hover selection surface; press forest inset indicator; disabled surface.disabled with secondary text and subtle boundary; saving dimensions stable. Show focus outside border.
- **Quiet/icon-only/destructive:** quiet 44px minimum hit area with primary text and underline for prose-like actions; hover selection background, pressed inset marker. Icon-only 44×44 target/20px graphic and accessible name; tooltip supplement only. Destructive mirrors primary geometry with error/errorHover/errorPressed and onAction text; disabled uses common disabled state. Destructive row actions stay secondary until intent is clear.
- **Passage/search/date/select field:** minimum 48px, 16/24 text, 12px horizontal padding, radius 8, 1px control border; visible 14/20 label 8px above. Focus common ring; error1px error border plus 14/20 error text 8px below with aria-describedby/invalid; error+focus shows both. Disabled common disabled surface plus explicit reason when consequential. Read-only retains primary text/panel border and “Read-only” context, not disabled opacity. Textarea minimum 104px, resize vertically; passage multi-entry may use textarea. Preserve typed value for errors, loading and failed saves.
- **Dropdown/popover:** panel/control border1px/radius 12/padding 8, overlay shadow; width content-driven minimum 200px/max viewport−32px. Rows 44px minimum/padding 12; selected selection background plus check/label; keyboard focus common ring. Native selects are preferred until custom behavior is justified. Surface never clips within map overflow; restore trigger focus after dismissal.
- **Tabs/segmented controls:**44px targets, 14/20 weight 600, 8px horizontal padding; selected forest text/selection surface plus 2px forest marker. Tab focus is separate from selection; arrow-key behavior only for genuine ARIA tabs. Filter buttons are ordinary pressed buttons when they do not expose tab panels. Preserve visible selection on hover/press.
- **Pagination/previous-next:**44px minimum target with readable “Previous”/“Next” or named icon; current page selection surface/forest marker; boundaries disabled. Avoid inventing pagination for infinite map navigation. Long history may paginate without changing current map reference.
- **History:** flat list, 1px subtle divider, 16px vertical padding, 12px gaps. Passage 16/24 weight 600; metadata 14/20; expanded notes 16/1.65 max 65ch. Selected row selection surface plus 3px forest edge. Per-row actions 44px targets; no uniform forced height.
- **Dialog/sheet:** width min(560px,viewport−32px), padding 24 desktop/16 phone, 12px radius, panel surface/overlay shadow, maximum available dynamic viewport minus 32px; inner content scroll, actions reachable. Title 24/32, close 44px, section gaps 24, action gap 8. Phone long forms may use full-height sheet with safe-area padding; retain title/return action. Focus trap/restore, Escape when safe, background inert. Do not demand destructive confirmation for every reversible low-impact operation.
- **Status/validation:** inline status panel padding 12/gap 8, 14/20 type, error surface+error border+explicit error text; success panel+forest/check and passage name. Toast max 480px and viewport−32px, padding 16, action 44px; wrap and announce politely for success, promptly for failures. Persistent/important recovery remains inline or recoverable after toast dismissal; no auto-dismiss of a required decision. Empty first-use and empty-filter states have distinct labels/actions.
- **Checkbox/radio:**20px mark within 44px labeled target, gap 8, label 14/20; forest checked state plus shape mark, 1px control boundary unchecked; common focus ring. Never use color-only checks or custom span click targets without keyboard semantics.

## Highest-priority missing specimens

1. Existing primary/secondary variants need **pressed**; PassageField needs hover, error+focus, read-only, help/long-value and processing specimens. Verify disabled legibility rather than treating opacity as sufficient.
2. Add navigation selected+focus, metric selection+focus, icon-only/destructive controls, checkbox/radio/select and textarea specimens. These are repeated throughout real flows and should establish reuse before more screen polish.
3. Add log form valid, parser error, error+focus, saving, storage failure and success/recovery; selected-map-range default+focus over darkest/lightest metric buckets; history expanded-note/long-reference; first-use versus filtered empty.
4. Add popup/dialog/sheet specimens at 390 and 320, including long title/notes, wrapped footer buttons, safe-area/nav/status overlap, keyboard focus and 200% text resize. Include 768 composition to preserve the established top-navigation adaptation.
5. Add import conflict, archived/read-only journal, backup/storage failure and undo notice examples. Specify shapes/type/layers using the same tokens rather than adding an isolated warning aesthetic.

Do not create separate full-screen variants for every combinatorial state; use component specimens plus representative end-to-end compositions. Review reference geometry, live keyboard behavior and actual state colors after implementation. Exact specifications make the draft reproducible; only actual rendered verification can establish that it works.
